# Source-qualified repeated sessions and production support cohort

## Scope and authority

`verifyRegionSourceSessionV8` collects two through sixteen independent calls to
the same exact source and entry, with one immutable program in one public V8
session. Each call has a fresh realm. Root invocation, realm, track, trigger and
session identifiers are assigned **before** the original source verifier runs.
Already certified record bytes and identities are never renamed afterward.

Every component passes the ordinary independent source/reference, projection and
replay checks. Composition reuses every generated line unchanged, recomputes its
causal context and region entry at the new public cut, and checks the complete
consequent observation batch. It deduplicates only an identical program
publication. The combined history must replay and survive JSON checkpoint
restoration with exactly the same completed states.

The private source collection binds every original component, its input graph,
public/context digests, source family, entry and collection plan. Recheck reruns
each original source check, reconstructs the composition, and compares the full
public/context history and sidecar evidence. A self-consistent replacement hash
cannot certify changed source, selected bytes, identities, provenance or family
membership. Controlled or unverified selection origins cannot become teacher
provenance. Original source authority and native admission remain separate.

The public V8 entry exports the direct collection and recheck functions. The
ordinary `verifyRegionTrainingCase` also accepts a `sessionCases` array and
routes it through this source-session verifier. Worker serialization preserves
each call's graph inputs, aliases, special values and fixture observations.

```js
const result = await verifyRegionTrainingCase({
  id: 'two-source-calls',
  family: 'the-original-source-family',
  sessionCases: [firstSourceFixture, secondSourceFixture],
  seed: 17,
  producerRevision,
});
```

Every declared call receives a disposition. A refused component prevents
partial session export; it is never removed from the denominator. Two callback
collections currently reuse callback identifiers and therefore refuse
composition. General callback identity namespaces, retained realms and dynamic
descendant composition remain outside this bounded profile. The current
production support cases use standalone callback/recovery executions and
callback-free repeated-root executions.

Source-only rechecking returns native admission as untested even when it checks
the structure and exact bindings of a persisted native receipt. An independent
consumer must freshly replay, check contexts/continuation/masks and source
correspondence, and verify the pinned production tokenizer before native
admission. The new private evidence schema does not change the public V8 wire.

## Frozen supporting population

The separate `se-support` population contains all sixteen existing authored
arithmetic recipe families. Each contributes exactly four variants:

| Variant | Purpose |
| --- | --- |
| Pure | Source invocation and compact computation |
| Callbacks and recovery | Async tool results, retained callbacks, source eviction/rereading and exact effect reconciliation |
| Two repeated calls | Two independently source-qualified fresh roots sharing the exact program |
| Child teacher | The pure source plus the ordinary source-qualified create/join/publish/complete teacher transcript |

All **64** declarations and their complete source relation registry are frozen
before executing any source. Seed **17** assigns **48 training, 12 validation and
4 test** source members. All variants of a family remain together through exact
source, source-derived compact core, original family and ancestor relations.
The seed and membership are never selected from execution outcomes. The fixed
cohort digest is
`13d83029df2237294608be8a127a1d8556fef24a9076d52b0f36741da5f74a15`.

This supporting population does not replace or shrink the **665 original** or
**66 selected** qualification populations. Every unsupported, unselected or
failed support member remains in its own 64-member denominator and frozen split.
The child variant uses the ordinary source-qualified teacher attaching API; it
does not attach a label to a detached parent pointer or fabricate model output.

## Collection and remaining production gates

Use the ordinary qualification command with `--population se-support --inputs
all`. It saves the complete encoded population, support cohort and family
registry before launching workers, and binds every successful export to its
exact predeclared source ID. `--cases` can select a bounded run while retaining
all other declared rows as untested. `--inputs first` is refused because the
repeated cases are part of the fixed declaration.

```sh
node tools/qualify-semantic-v8.mjs \
  --population se-support --inputs all --workers 2 \
  --out /absolute/path/to/support-qualification --prepare-only
```

Remove `--prepare-only` and supply the existing exact native checkout, Python,
tokenizer and policy arguments for independent admission. Source-only results
do not establish production supply. The subsequent ordinary preparation gate
must materialize every declared member and retain the same registry. The
unmodified production SE behavior requirements must pass on **both training and
validation** using actual admitted records, including the coordinator targets.
Every expected source ID, including the held-out test members, must remain in
the prepared inventory. Complete launch assets, donor curriculum, optimizer
exposure and learned-quality studies are separate acceptance work.

Local receipt tests deliberately use labeled receipt doubles and byte-fallback
controls where applicable. Their successful structural checks do not qualify
production tokenizer bytes or independent native source correspondence.
