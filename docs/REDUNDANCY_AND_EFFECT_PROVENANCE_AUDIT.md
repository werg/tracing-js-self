## Changes in this PR

1. **Bind each external effect to the exact originating owned call.** The independent host-journal verifier now checks the frame, source site, host function token, evaluated tagged operands, and operand-origin sequence against the effect's creation mutation *before* checking canonical prepared JSON and graph versions. The restricted causal prefix includes opaque argument identities and supplying-event pointers next to the existing immutable payload; delivery is still withheld until legal arrival.
2. **Stop replacing evaluated arguments with a JSON parse.** The private normalized semantic `request` now preserves identity-bearing `effect.args` plus `argOrigins`, while carrying immutable payload bytes separately. `request` remains an auditable semantic event even while its public compilation is refused.
3. **Make v3 selected `request` unambiguous.** A generated request must include an active invocation ID, a precise Acorn `CallExpression` source span for a registered direct host call, tagged arguments, and canonical JSON bytes. The controller checks that the declared operation matches the site, re-materializes refs using `src/host/materialize.js` over the *current* committed public heap, and rejects any mismatch transactionally. Thus there is one codec for executing and checking host requests rather than a second primitive-only request path.
4. **Preserve observable external ordering.** Deterministic fixture replies are consumed in order, never selected by unordered search; status/results remain environment-only observations. Continuation packets preserve claimed fixture state, generated-record limits and packet limits so a resumed controller does not quietly reset effect authority.
5. **Remove the obsolete raw archive reader switch.** `semantic-tracing-run/1` is no longer accepted by current reconstruction or causal publication. Previous archive files are not rewritten by this PR; old archives need explicit offline migration through the historical reader, followed by v2 validation/replay.
6. **Add adversarial regressions.** Tests cover forged source-site/activation/payload/argument claims, ordered fixtures, checkpoint restoration, current-state object materialization and tampered raw call-to-effect provenance.

The new request requirements are a **deliberate stricter subset of the existing v3 request opcode**, not a claim that old effectful training episodes were admitted: the teacher compiler has always refused those effects. Any external v3 request emitters (including paired importers/tests) must adopt the required fields and ordered fixture contract rather than adding a backwards-compatible dual decoder.

## Source-level binding and honesty limits

- A callsite is a UTF-16 source `start:end` interval that Acorn identifies as an actual `CallExpression` whose direct `host.*`, `Date.now()` or `console.*` callee resolves to the declared host operation. It is checked relative to the active selected invocation. This does not yet prove full dynamic lexical binding of arbitrary aliased or computed call targets; unsupported forms should be refused for effectful supervised compilation.
- Tagged arguments must be canonical scalar/ref tokens. Each ref resolves against current selected state; the single owned host codec rejects cycles, repeated identities, sparse arrays, unsupported numbers, undefined and rich guest identities. Frozen JSON bytes record the exact materialized snapshot at request time. **The serving controller is not an independent JavaScript interpreter:** validating that the claimed primitive argument *arose from executing the source expression* still requires teacher-side call-event provenance and independent outcome/effect checks.
- No original source `sites` table or journal counter is added to model-visible context; the controller parses already-published source at initialization. The raw archive retains private `argOrigins` / identity and commit ordering.
- The current compiler and admission gates remain fail-closed for effects. Do not mark these cases admitted, make a hidden host execution shortcut, or invent new parallel witness variants to bypass certificates.

3. Admit effectful data only after independent external fixture assertions check dispatch count, exact arguments and order, final reachable graph, rejection and cleanup.
4. Coordinate the **one** v3 request grammar update with the pinned `megatoken` importer and any downstream producers; do not ship a second parser for the old ungrounded request form.
5. Consolidate module/frontend and general-prefix projections only with consumer migration receipts and broad parity suites.
