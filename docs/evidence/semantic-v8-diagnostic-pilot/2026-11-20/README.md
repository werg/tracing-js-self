# Native v8 diagnostic fitting and frozen execution pilot

Both bounded diagnostics completed as experiments. Neither model completed a
JavaScript execution: each frozen study attempted both declared cases and
reported **0 of 2 completed executions**. All original malformed output, token
identities, failures, costs, source receipts, and frozen denominators are retained.
The fitted weights are also archived in full.

This evidence establishes that admitted data can reach the actual native decoder
optimizer, be exported and reloaded, and reach the producer's frozen execution
study through the real Python subprocess. It does not establish a learning
benefit, generalization, production training readiness, or default promotion.

## Scope and split roles

The two source cases already belong to the gallery population:

| Case | Source operation and input | Existing family-hash split |
| --- | --- | --- |
| `compound-pure` | `(a+b)*(c+d)+1` for `[1,2,3,4]` | `test` |
| `pure-helper` | An owned `increment` helper called with `4` | `train` |

The initial diagnostic selected `compound-pure` for optimization and kept
`pure-helper` outside its gradient updates. During evidence packaging, their
existing corpus split labels were checked. The initial diagnostic therefore
cannot be presented as a corpus train/test evaluation. It remains archived in
full as **preliminary**, including its failures and costs.

A second, independently initialized diagnostic used the existing split roles:
`pure-helper` supplied optimizer targets and `compound-pure` was evaluation-only.
This is **family-split** in the archive. It reused no weights or optimizer state
from the preliminary fit. It remains an exploratory two-case diagnostic, not a
formal held-out benchmark: the preliminary experiment had already exposed both
cases in different roles, and there is no generalization claim.

Both fits used seed 17, four decoder-only optimizer updates, learning rate 0.02,
the tiny native model, CPU execution with one thread, and the locked production
Ling tokenizer. Native boundary capture and the grouped trainer supplied the
training states. The text decoder changed; the model's other parameter owners
were verified unchanged. No expected target or private source sidecar was sent
to the serving selector or used to repair a model output.

Each model's frozen study declared the same two cases and seed before the
producer study made its first model call. Settings were exactly
`{"device":"cpu","maxTokens":64,"maxFragments":1,"effort":1}`. Per execution,
the study allowed four predictions, four generated records, four outstanding
tasks, zero stale retries, and a 60-second deadline. The fitting script's own
baseline/intermediate/final checks are separate from these frozen studies.

The decreasing diagnostic loss did not produce a successful execution. Both
models emitted text that the producer rejected as an unsupported v8 record on
their first prediction. There were no accepted records, host dispatches, or
source-qualified completed executions. Their actual original bytes and token
IDs remain in the reports, including rejected predictions.

Across the two distinct frozen checkpoints, accounting totals are 4 attempted
executions, 0 completed executions, 175 authenticated generated tokens, and 954
generated bytes. This is an accounting total, not an independent benchmark
estimate. Each report keeps its own full denominator of two.

The fitting scripts also retained five native inference evaluations per model:
baseline training/evaluation-only cases, an intermediate training-case check,
and reloaded final training/evaluation-only cases. All ten failed to complete.
They emitted another 253 and 192 measured tokens respectively, retained in the
fit reports rather than silently included in the frozen-study rate. The study
reports say `optimizerSteps: 0` because inference performs no optimization;
the separate fit reports record the four actual updates for each checkpoint.

## Inspect or repeat

Reassemble and extract in a new directory:

```sh
mkdir extracted
cat fitted-bundles.tar.gz.part-* > extracted/fitted-bundles.tar.gz
sha256sum extracted/fitted-bundles.tar.gz
tar -xzf extracted/fitted-bundles.tar.gz -C extracted
tar -xzf evidence.tar.gz -C extracted
```

Check the archive hash above and the per-file manifest at
`extracted/evidence/evidence-files.json`. The served loader also checks the
weight, tokenizer, configuration, and memory hashes against each bundle's
manifest. The extracted `fitted-bundles/family-split` directory is the complete
final diagnostic serving bundle.

For a new run, create separate clean checkouts at the three pinned revisions,
install the producer lockfile dependencies and the recorded Python environment,
then run:

```sh
python reproduce.py \
  --evidence extracted/evidence \
  --training-producer /absolute/path/to/producer-653fd1b \
  --evaluation-producer /absolute/path/to/producer-62eb943 \
  --consumer /absolute/path/to/consumer-23cd478 \
  --python /absolute/path/to/venv/bin/python \
  --tokenizer extracted/fitted-bundles/family-split/tokenizer.json \
  --output /absolute/path/to/new-diagnostic-output
```

Source receipts bind Node, dependency, locale, and verifier identities, so a
different source environment is expected to refuse the archived inputs. In that
case, freshly prepare and admit the same source cases under the new environment
and freeze a new study; do not rewrite the archived receipts. New timing and
floating-point results need not be bit-identical on different hardware. This
archive preserves the exact measured weights and original observations.
