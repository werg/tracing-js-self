# Original input and physical source authority in direct V8 releases

Each release source descriptor now contains three separate fields: `caseId`,
`sourceId`, and `path`. A case label is the frozen task's identity. A physical
source ID is the corresponding member of the frozen family registry and may
include a digest suffix generated by `regionFamilyMembership`. An artifact
filename is a retained locator. The release never derives a physical source ID
from the case label or filename.

Before preparing release inputs, the read-only campaign verifier binds every
source-qualified historical attempt to its original encoded task. It selects the
explicit physical source ID from that attempt's committed row, then compares the
registry member's original source, entry, family, normalized ancestry, complete
split identity and dataset binding. Source text, canonical argument graphs,
aliasing, host calls and settlement order, guest RNG settings, ordered session
components, original module requests, and teacher transcript requirements remain
part of the task comparison. The Python packager and restorer derive descriptor
membership only from the resulting independently checked snapshot. They reject
missing or mismatched task bindings, invalid memberships and duplicate physical
source IDs. The native verifier independently requires the same explicit
`sourceId` to match the artifact before fresh preparation.

These are correspondence checks over retained evidence. The hash-linked campaign
is not an authenticated external signature. Fresh original-source rechecks,
native admission, preparation equivalence and model-state verification remain
required on the exact trusted checkouts. For module cases, the snapshot binds the
original graph, entry, export and argument or ordered-call graph; subsequent
fresh module rechecking relinks that original request and verifies its generated
source, metadata and original ESM outcome. The snapshot alone does not perform
that semantic replay. Transformed tasks carrying `originalReferenceSource` still
refuse until they have an explicit original-source correspondence profile.

## RNG semantics follow actual source admission

`createSourceAdmissionClient` falls back to `seeds.guestRng` when `randomSeed` is
omitted. An explicit `randomSeed: null` stays null, and an explicit zero stays
zero. `normalizeSeeds` refuses a conflicting declared `seeds.guestRng`. For
example, `{randomSeed: null, seeds: {guestRng: 19}}` is refused before source
execution. It must not be reinterpreted as a request to execute seed 19. The
release correspondence check now enforces that same distinction, with actual
source-admission controls for zero, omission, null, matching guest seeds and both
conflicting null/19 and zero/19 declarations.

## Reconciliation of the alternate original-input controls

The independent proposal at producer `729a05507f20242514c81f2e8f7979c2ccaac1f5`
contains eighteen controls. Its useful assertions are retained in the existing
JavaScript task/campaign boundary and the descriptor controls; a second Python
semantic verifier is not introduced. The correspondence is explicit below.

| Alternate control | Composed coverage or decision |
| --- | --- |
| Case label differs from physical source ID | Actual source admission plus `regionFamilyMembership` creates a digest-suffixed identity; registry binding and the descriptor preserve that identity separately from the case label. |
| Original source changes | Existing source/task substitution controls and the preserved original 64-source safe-artifact swap refuse. |
| Original entry changes | Existing task-entry substitution control refuses. |
| Arguments change | Existing canonical graph substitution controls cover changed numbers, scalar types and aliasing. |
| Host fixture changes | Existing source host-call and session callback-outcome substitutions refuse. |
| Settlement order changes | Added explicit retained host-schedule substitution control refuses. |
| Original family changes | Existing family substitution control refuses. |
| Original ancestry changes | Existing different-ancestor substitution control refuses. |
| Equivalent normalized ancestry | Added normalized set control accepts repeated ancestors and the family's own label; an additional ancestor still refuses. |
| Producer and task identities change | Existing producer revision and task ID substitution controls refuse. |
| Physical source ID changes | Added missing, case-label and other-physical-ID controls refuse against the original frozen registry. Native descriptor controls independently reject mismatched source IDs before preparation. |
| Dataset split changes | Added explicit dataset-binding split mutation refuses against the complete original split identity. |
| Nullish RNG fallback | Corrected to actual source-admission semantics described above; the proposed null/19 positive is invalid. |
| Module tasks always refuse | Replaced by the already qualified explicit module-request correspondence plus fresh relinking. Blanket refusal would discard the existing original graph, alias and ordered-call controls. |
| Teacher transcript presence changes | Existing teacher-required and unrequested-teacher controls refuse; actual source teacher evidence has a positive control. |
| Repeated invocation order, count and inputs | Existing actual ordered-session controls preserve every component and refuse reordering, omission, input changes and callback-outcome changes. |
| Empty direct-protocol host plan omission | Existing actual direct-protocol positive retains its omitted empty plan; an added nonempty required host plan refuses. Actual mixed host-protocol evidence must retain the exact plan. |
| Raw source bytes change outside inventory | Added a whitespace-only source-file mutation alongside existing admitted-file, missing-failure and journal/CAS byte controls. Exact inventory checks refuse even when parsed source JSON is unchanged. |

The original 64-source packet and the two separate preserved red packets remain
distinct controls: original task/source substitution and admitted/native-only
substitution. A changed descriptor or successful local assertion does not upgrade
an earlier hosted run. The composed pair must complete a new frozen end-to-end
release qualification with its own archive bytes and independently retained hash.
