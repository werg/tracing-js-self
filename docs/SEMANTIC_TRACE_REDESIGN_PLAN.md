# Complete semantic trace redesign plan

Date: 2026-10-24

Status: implementation plan; the changes specified here are not yet implemented.

Execution model: one continuous implementation effort, ending when the complete acceptance contract in this document is satisfied.

## 1. Objective and execution contract

Build a compact, understandable language of execution reasoning that teaches a model to compute correct results and perform correct observable effects. Preserve exact execution evidence privately. Give the public reasoning trace freedom to combine, omit, rename, and normalize internal operations when the resulting account remains coherent and the observable behavior is correct.

Implement **all** requirements in this document as one integrated change. The sections describe responsibilities and dependencies, not separately approved phases, optional follow-ups, partial releases, or stopping points. Continue from implementation through regression repair, corpus regeneration, downstream integration, model evaluation, documentation, and final verification. A passing intermediate test or a smaller demonstration trace does not complete the work.

Resolve routine implementation choices within the contracts below. Run independent work in parallel where useful, integrate dependent changes as their interfaces become available, and keep working through failed checks until they pass. Do not insert approval checkpoints between components. Genuine unavailable credentials, execution capacity, or external services must be recorded precisely as unresolved dependencies; they must never be converted into fabricated results or a claim that the complete plan is finished.

Reuse verified work already present on the current base. Preserve concurrent repository changes, and implement missing behavior without repeating settled patches or reverting newer runtime capabilities.

This plan is the implementation authority for the redesign. It updates the direction in [TRAINING_DATA_PLAN.md](TRAINING_DATA_PLAN.md) and [EFFECTIVE_TRACE.md](EFFECTIVE_TRACE.md) in four respects:

- Public correctness does not require the teacher's source-event decomposition, branch count, temporary variables, object names, or exact bytes.
- A dedicated compiler produces the public reasoning trace from verified execution evidence; the detailed normalized journal is not itself the public contract.
- Granularity and explanatory primitives are measured design choices, evaluated using actual model-selected execution.
- The complete delivery includes the bounded effect, completion, scheduling, and downstream consumer paths specified here, rather than ending at a synchronous compaction demonstration.

The completed implementation must keep source-language coverage, public trace vocabulary, observable-boundary semantics, and dataset admission status separate. A small public vocabulary can describe rich supported execution without claiming full JavaScript or Node/browser compatibility.

## 3. Three explicit correctness contracts

Use the following names in APIs, reports, tests, and documentation.

| Contract | Required meaning | Independence from the teacher |
| --- | --- | --- |
| **Observable execution correctness** | Completion, declared reachable state, ordered external effects, delivered observations, and required pending-work disposition agree under the same environment contract. | Internal reasoning, trace length, source decomposition, allocation names, and trace bytes may differ. |
| **Witness consistency** | Emitted claims are well-typed, internally coherent, compatible with committed state, and correct under the declared primitive semantics. | A valid explanation need not reproduce the teacher's temporary variables, source branches, or calculation boundaries. |
| **Artifact integrity** | A generated demonstration has the declared versions/policies, verified source execution, justified transformations, valid serialization, and correct consumer import. | Canonical-byte equality is a regression property of a particular generator, not the definition of model execution success. |

Observable execution correctness is the primary task metric. Witness consistency is a separate data-quality and diagnostic metric. Artifact integrity is required for emitted training demonstrations.

Retain private exact replay and independent V8 outcome/operation/branch evidence. Those receipts establish the source execution used by the generator. Do not impose their exact event sequence on an alternative public derivation.

Replace the ambiguous exact-string diagnostic `firstDivergence` with `firstReferenceTraceDifference`. Report `firstWitnessViolation` and `observableMismatch` separately. A harmless identity rename, fused assignment, or different valid derivation must not be reported as an incorrect computation solely because its text differs.

The selected-trajectory evaluator must report outcome-correct but mathematically inconsistent traces honestly in both categories. It must not repair the inconsistency or reject an otherwise correct task outcome merely to force agreement with the canonical teacher. A malformed or unsafe action can still be rejected by the serving transaction validator.

## 4. Bounded observable and execution scope

### 4.1 Data graph

Define one graph contract shared by input import, context publication, independent reference construction, controller state, continuation packets, and outcome comparison. Include:

- Primitive values with exact supported distinctions: `undefined`, `null`, strings, booleans, finite numbers, signed zero, `NaN`, infinities, and BigInt where supported.
- Plain objects and ordinary arrays with stable semantic identity, aliases, cycles, own-property presence, enumeration order, and array length.
- Explicit distinction between an array hole and a present element whose value is `undefined`.
- Explicit ordinary-versus-null prototype classification for accepted plain objects; the current importer accepts null-prototype objects, so reference and public paths must preserve that distinction.
- Roots for supplied arguments, returned/thrown values, and any captured state explicitly declared observable by the execution envelope.

Support sparse data graphs consistently across the new boundary: remove dense-only import/public-validation assumptions, retain presence bits, and verify every admitted operation over those graphs. A builtin whose sparse behavior has not been independently verified remains outside that operation's declared supported domain; do not silently densify its input.

Custom prototypes, accessors, closures, promises, and other supported identities may exist internally. Rich behavioral objects crossing the observable boundary require an explicit representable contract. Reject unsupported boundary values rather than flattening them into ordinary objects and claiming general JavaScript equivalence. The data comparator is not a proof of all possible future interactions with an arbitrary JavaScript object.

For this delivery, accepted boundary objects are extensible and have ordinary own data properties that are writable, enumerable, and configurable. Ordinary array `length` has its standard nonenumerable, nonconfigurable, writable descriptor. Input import and terminal extraction inspect descriptors without invoking guest code and reject accessors, nonstandard data-property attributes, frozen/sealed/nonextensible objects, and nonstandard array-length attributes outside a separately declared supported contract. Do not reconstruct such inputs with different attributes. Internal descriptor changes remain supported where owned; if the resulting richer object reaches an observable root outside this boundary, report an unsupported observable boundary. Classified guest errors use the separate bounded error-value contract, not accidental flattening through this ordinary-data rule.

### 4.2 Completion

Include normal return, explicit primitive/plain-data throw, and the existing bounded classified guest errors. For classified errors, compare declared semantic fields such as name/message and reachable data; native stack strings, Error prototype identity, and host exception identities are outside this contract.

Interpreter failures, resource limits, unsupported features, and invalid generated actions remain separate result categories. They are never converted into successful returns or guest exceptions merely to finish an episode.

### 4.3 Effects and jobs

Include the registered operations in [host/operations.js](../src/host/operations.js): `demo.readNumber`, `demo.readAsync`, `demo.store`, `platform.dateNow`, and the registered console methods. Expose them through explicit capability declarations and deterministic test environments.

Include existing owned async functions, `await`, supported Promise fulfillment/rejection/adoption and reactions, and the single-agent FIFO `queueMicrotask` behavior already documented in [PROMISE_REACTIONS.md](PROMISE_REACTIONS.md). Reuse existing owned implementations; the work here completes their coherent training representation, reference checking, and serving integration.

Do not expand this delivery into wall-clock timers, Node `nextTick`, workers, shared-memory agents, browser rendering checkpoints, arbitrary native callbacks, unrestricted thenables, Promise species/subclassing, full Promise combinators, or universal ECMAScript support. Maintain an explicit operation/capability table distinguishing supported runtime execution, independent evidence, public witness support, and dataset admission.

An episode declares its completion policy before execution. Provide an immediate-root-completion policy that refuses outstanding required work, and a root-settlement-and-owned-quiescence policy that includes the required owned jobs/effects. An unresolved required effect or promise is an incomplete execution, not permission to fabricate an end record. Detached/unhandled work follows an explicit bounded policy; do not drain unrelated work opportunistically to make an example pass.

Fix that policy as follows: under immediate-root completion, any remaining program-scheduled job or required outstanding effect makes the episode incomplete. Under root settlement and owned quiescence, every job/effect scheduled by the admitted program belongs to the episode, including work detached from the returned value. It must reach its declared disposition. A synchronous uncaught microtask exception produces the bounded terminal guest failure with earlier effects retained. A rejected promise still unhandled at quiescence is outside the admitted training contract and produces a distinct `unsupported.unhandled-rejection` result; do not invent Node/browser rejection notifications or silently report success. Required pending work at a resource limit remains incomplete.

## 6. Public reasoning language

Retain the simple **operation name followed by canonical JSON** line envelope. Redesign the payload around semantic work. Publish a schema and parser for the new typed records; reject unknown fields, noncanonical scalar values, malformed identities, and unsupported operation domains.

| Operation family | Semantic content |
| --- | --- |
| Compute/bind | A bounded primitive expression, its supplied result, and optional named destination |
| Choose | The evaluated test and selected continuation, including short-circuit behavior |
| Allocate | A new object, array, closure, or shared cell with its meaningful initial state |
| Read | A location and observed value when a separate read boundary is useful or required |
| Write/delete | A committed property or shared-cell mutation, with exact presence semantics |
| Call | Callee, evaluated receiver/arguments, and return binding; opens one activation |
| Completion transfer | Raised value and handler/cleanup routing when execution continues |
| Return/terminal throw | Actual invocation exit and its value |
| Request/observe | Semantic external operation/arguments and the corresponding delivered result or rejection |
| Owned promise/job transitions | Promise creation/settlement/adoption, observer registration, enqueue, and legal dispatch under the bounded scheduler |
| Suspend/resume | Supported continuation and scheduling boundaries |
| End | Declared terminal episode boundary after completion-policy checks |

Use one computation/binding form for declarations, ordinary assignments, and compound assignments when they have the same effective meaning. Names are scoped by the active semantic invocation. Introduce short public object, cell, invocation, and reusable-result identities only where they express a real relationship. Keep their namespaces distinct.

A public primitive expression uses a closed typed grammar of literals, committed local/cell/temporary references, declared ordinary-data reads, and supported operators. It does not invoke arbitrary JavaScript. It may refer to a published semantic source expression when that expression fully specifies the calculation; synthesized alternative expressions carry their own bounded typed expression. Source attribution is optional provenance, and an explicit source claim must be checked.

The default explanatory policy shows one nontrivial arithmetic or logical calculation per computation record, absorbing routine operand retrieval and its destination update. The compiler also implements bounded fusion policies with maximum operator counts of 2, 4, and 8 for the required experiments. These are policies over the same grammar, not incompatible wire formats. Freeze the chosen policy in each corpus/model manifest before generation. Select the shipped default using the evaluation rule in section 16; retain the conservative policy if the evidence is inconclusive.

Define `operatorCount` as arithmetic, comparison, logical-choice, conversion, and other registered nontrivial primitive applications in the expression. Literal/local/property-read leaves and a destination commit are counted separately as `operandCount` and `mutationCount`; they do not consume that operator limit. Enforce a maximum of thirty-two expression nodes and the real token limit as well, so an arbitrarily long read tree cannot evade the bound. Report all three counters. Every fusion-policy and region-operation limit in this document refers to `operatorCount`.

The following is an illustrative rendering of typed records, not a second parseable wire grammar:

```text
call run(a=&a)
sum = 0
i = 0
choose i=0 < a.length=3 -> continue
sum = 0 + a[0](2) -> 2
i = 0 + 1 -> 1
choose i=1 < a.length=3 -> continue
sum = 2 + a[1](3) -> 5
i = 1 + 1 -> 2
choose i=2 < a.length=3 -> continue
sum = 5 + a[2](4) -> 9
i = 2 + 1 -> 3
choose i=3 < a.length=3 -> exit
return 9
end
```

Do not require a duplicate generated `enter` after a call that already opens the activation. The root's invocation facts may be initialized from observed entry context. Derive ordinary return destinations from the committed call structure. Code, receiver, arguments, captures, and lane assignments must not be copied into multiple targets merely to synchronize components.

Retain exact supported scalar tagging in the wire codec, with familiar human spellings in the renderer. Replacing typed values with ordinary JSON numbers must not lose `-0`, nonfinite values, or BigInt. Preserve aliases, holes, and present-with-undefined separately from absence.

## 7. Compaction rules and certificates

Implement a closed, versioned rule registry. Each rule states its input pattern, static/committed-state preconditions, public output, effect boundaries, scalar semantics, and certificate checks. Unknown effects conservatively prevent an optimization; they do not cause guessed purity.

### 7.1 Operand absorption and destination fusion

Absorb literals and reads of ordinary unescaped locals into the consuming calculation. Fuse a pure computed result with its immediate binding write or branch decision when no other use or observation requires the temporary. Keep a named temporary when it is reused, crosses a boundary, or explains a meaningful calculation.

Absorb proven ordinary data-property reads into nearby calculations when the record still specifies the operands used and the read crosses no relevant effect. Do not turn a getter, proxy access, conversion hook, external observation, or unknown read into an implicit pure load.

Preserve JavaScript operator order, floating-point rounding, signed zero, exceptional behavior, coercion, and string concatenation. Do not apply mathematical reassociation to Number arithmetic. Preserve left-to-right operand evaluation and exactly-once evaluation of effectful operands.

### 7.2 Repeated reads and dead private work

Reuse or absorb an unchanged ordinary-data read only while committed location state and the region's effect information justify it. Invalidate the proof after a relevant write, unknown guest call, accessor/trap, suspension, external observation, or other possible writer.

Use conservative static liveness and escape/capture analysis to omit dead private loads, temporaries, and overwritten ordinary local writes. Do not select an earlier explanation by inspecting the eventual answer. Eliminate a same-value write only after proving that its evaluation, dispatch, and intermediate state have no relevant observation; equality of final heap values alone is insufficient.

The compiler may buffer the bounded source-defined expression or region it is currently explaining. Its policy and flush decisions must be reproducible from static source plus available committed events, without a future branch, final result, or private arrival deciding earlier visible content.

### 7.3 Loops and captured cells

Represent loop progress through actual choices and changed loop-carried values. Remove mechanical backedge narration when the continuation is already explicit. Hide per-iteration environment allocation for uncaptured bindings.

Preserve mutable captured cells. Two closures created in the same iteration can share one cell; closures from separate `for (let ...)` iterations can need distinct cells. An update within the body changes the cell seen by that iteration's closures. Never substitute universal captures-by-value for shared storage.

Equivalent source loop forms may lower to the same iteration primitives. The canonical explanatory policy retains enough per-iteration calculation to support learning. Larger loop summaries are admitted only as declared bounded primitives with verified semantics and are included in the model comparisons; a final answer cannot be smuggled into an unexplained summary.

### 7.4 Allocations and ordinary collection mutations

Combine fresh ordinary object/array initialization after its element/property computations have completed when the identity cannot be observed during partial construction. Preserve every call and effect that computes the initial contents. Preserve aliases by storing references rather than deep copies.

Express array length and presence directly. Eliminate synthetic length increments from fresh literal construction. For already published arrays, support atomic semantic mutations such as append or truncation only with declared rules that preserve values, holes, aliases, and the expression result. Derive mechanically implied length changes from the committed operation; do not calculate missing guest values.

### 7.5 Calls, pure helpers, and collection callbacks

Inline supported pure helpers when conservative effect analysis and bounded expression rules justify it. Keep their source/private invocation provenance without requiring the public trace to reproduce call scaffolding. Retain dynamic calls when they explain reusable code, shared state, callbacks, exceptions, or other observable behavior.

Give collection traversal and callback execution distinct semantic ownership. Publish output allocation once, obtain each current input value, execute the callback, then insert its result or update the accumulator. Preserve each operation's length-snapshot, presence, and visitation rules. A callback's mutation of a later input must affect that later read when JavaScript requires it.

Do not precollect all callback inputs from the original array. Do not collapse callback-bearing methods into opaque host results. Stateful sort comparators require an explicitly supported callback-order contract and independent evidence; if host-dependent comparator ordering prevents that contract, classify the case as unsupported instead of inventing a common order. Pure deterministic builtins use a finite primitive registry with an explicit domain and checked semantics.

### 7.6 Private transformation certificates

For each emitted record, retain privately:

- The supporting normalized events and original journal events.
- Applicable source spans and static analysis facts.
- The selected rule and its version.
- Required starting location/value facts and dependencies.
- The resulting value, writes, identity relations, and preserved boundaries.
- The relevant independent source-execution evidence.

Permit many detailed events to support one public record, multiple public facts to arise from one runtime event, and bookkeeping events to have no public narration. The evidence checker independently verifies each registered rule's preconditions and result; it must not trust a compiler assertion that something is merely "equivalent."

Certificates and exact canonical compiler regression tests establish demonstration integrity. Public selected-trajectory validation must not require a private teacher certificate or a matching teacher decomposition.

## 8. Complete semantic invocation and completion normalization

### 8.1 One representation for every guest call

Introduce a structured semantic invocation fact for all existing paths that execute guest code: ordinary calls; getters/setters; supported proxy traps; `valueOf`/`toString`; array callbacks; supported sort and replacement callbacks; Promise reactions/cleanup; and owned microtasks.

Capture caller, callee/code, receiver, evaluated arguments, captures, return destination, and dispatch relationship once. Derive this from actual owned frame creation and call continuation data, rather than an open-ended list of operation-name guesses. Validate the fact against the private journal.

Handle `spec.internal.call` explicitly: it creates a guest frame even when its cause is a spec operation rather than an ordinary invocation. Every retained guest body must have a corresponding public activation or a certified pure inline expansion. No event may appear in an unentered or prematurely closed activation.

Normalize callback continuation work at its true semantic point. Output insertion, accumulator update, or replacement append belongs to the enclosing collection operation after callback completion. Keep the effects visible even if a permitted fused record carries them.

### 8.2 Pending returns, exceptions, and cleanup

Detect actual completion transitions rather than mapping every `call.return` event directly to terminal public `return`.

When a return expression has been evaluated but cleanup remains, bind its value to an ordinary pending-outcome temporary. Execute cleanup. Emit the actual return only when the invocation exits. A cleanup return or throw replaces the pending outcome. A saved reference retains identity; a saved primitive retains its original value. Never reevaluate the original return expression after cleanup.

Normalize actual exits occurring through return, throw, `completion.finally.end`, cross-frame unwinding, and classified owned faults. Model a locally caught raise as a nonterminal completion transfer; bind the catch variable through ordinary binding semantics. Terminal throw closes only the invocation that actually exits. Caller handling and finalizers can continue.

Keep handler instruction addresses, operand-stack restoration, private frame numbers, and completion-record implementation details outside generated targets. Preserve semantic routing, thrown identity, cleanup order, shadowing, and already committed effects. Release a lane only at actual invocation completion.

Remove the categorical caught-throw export rejection only together with the completed reference, normalizer, scheduler, causal auditor, controller, and rollout implementation. No isolated gate deletion is an acceptable implementation.

### 8.3 Accessors, inherited reads, and descriptor effects

Remove private shape/version predictions from the public state contract. The controller's own revision bookkeeping advances from public semantic commits; it must not assume equality with hidden runtime counters.

An inherited effective read can state the observed value without narrating the prototype walk. Do not present `present:false` next to an inherited value as if the property were absent; use an explicit own-presence fact only when it is semantically needed.

Preserve dispatch-changing mutations. A compact accessor binding or other declared semantic dispatch fact can establish that reading a property invokes a particular function. Executed accessors then use ordinary calls. Hiding descriptor flags must not erase behavior that a subsequent operation observes.

The effectful getter regression must succeed without introducing a meaningless public shape-counter bump. Setter assignment retains its assigned RHS as the assignment-expression value even when the setter returns another value. Getter-produced methods retain the receiver required by the subsequent call. Accessor/conversion throws use the same completion model.

## 9. Controller state and witness checking

The serving controller owns mechanical event numbering, default active invocation, public allocation assignment, private semantic revisions, lane allocation, and transport bookkeeping. These are deterministic consequences of committed actions, not generated semantic predictions.

Distinguish scoped witness-local names from controller-owned semantic identities. A fresh allocation maps its witness name to a fresh controller identity; later references resolve through that mapping. Do not require the teacher's canonical spelling. A consistent fresh-name renaming preserves meaning, while merging distinct allocations or reusing an active name incorrectly is rejected. Preserve the mapping and identities across continuations. Apply the same principle to meaningful cell/invocation/result names without exposing private engine counters.

Retain explicit relationships that are not implied by committed serial order, including shared cells, cross-invocation results, asynchronous dependencies, effect associations, and pending continuations. Derive none of them from a future teacher row.

Commit supplied values and mutations atomically. Validate references, location kinds, ownership, capability grants, array rules, invocation state, completion routing, and legal observation/scheduling boundaries. Rejected records leave the complete prior controller state intact, including allocation counters, fragments, pending completions, and ready queues.

Implement a small independent checker for the public primitive language. It reads the model's explicit operation and committed operands, computes only what is necessary to judge that claim, and reports consistency. It does not run missing guest JavaScript or insert a result the model omitted. Keep this checker separate from the owned source interpreter to avoid validating a shared implementation defect by self-replay alone.

Default rollout evaluation to no feedback and no repair: commit structurally acceptable selected records, then record reasoning violations without replacing values or supplying corrected continuation state. Check final observables from the actual selected state. Structural violations that make continuation undefined or an action invalid fail that execution. If a feedback/repair experiment is implemented, label and score it separately, including its extra computation.

Capture immutable operand values and relevant read facts from the selected pre-commit state at transaction start. Check an accepted claim against that captured state after committing its supplied output. In particular, `x = x + 1` must be checked against the old `x`, not the newly written destination. A reasoning violation never substitutes a correct value or changes the subsequent selected state.

A compact primitive must have independently specified/checkable semantics. It cannot become an arbitrary answer-bearing macro whose only justification is that its final value matches the teacher.

## 10. Source context, visibility, and rendering

### 10.1 Source and input publication

Construct observed program context solely from source, the declared execution contract, and supplied initial state. Build semantic sites from expressions, statements, declarations, and meaningful roles; deduplicate equivalent spans. Do not publish sites solely because a bytecode instruction, stack shuffle, scope teardown, or implicit housekeeping action received a span.

Never prune the initial site dictionary using the eventual executed-site set. The same source and declared entry produce the same initial source dictionary across different input values and early termination points. Do not reveal future target count, output-dependent identities, future callees, or future branches through layout choices.

Publish the source required for the entry and its statically selected dependencies. Support code-on-call for further registered code: a committed selected call resolves to a static code bundle, the loader publishes exact source as observed context, and generated callee work follows. The loader provides code, never an executed result or future capture values. Source registry and bundle policy are fixed before the episode.

Publish compact input graphs with semantic identities and required presence/prototype information, without initial engine shape/property counters. Preserve stable identity across repeated publication and continuations.

### 10.2 Complete inspection output

Implement rendering over the typed public records and earlier committed public state. Show every allocation, write, delete, call, and completion effect regardless of which record carries it. Allocate records must show identity, kind, and meaningful contents; callback calls must identify the actual invoked function and traversal context.

Fail explicitly for unsupported semantic payloads instead of silently hiding them. Add coverage that rejects bare `allocate`, empty mutation explanations, unexplained object identities, duplicated calculation/binding narration, and `undefined` call targets caused by renderer omission.

The renderer must not consult the private final heap or future records to explain an earlier step. Retain raw generated strings and rendered inspection text separately. Reports identify exactly which representation is being measured. The pretty renderer is not an unacknowledged replacement for the actual training target.

## 11. External effects, observations, and bounded async integration

### 11.1 Requests and immutable materialization

The model supplies the semantic operation and arguments once. Resolve its declared signature, codec, frozen payload, and byte count deterministically from the registered operation and committed graph. Preserve the existing guarded materialization behavior and capability checks.

Materialization must not invoke hidden getters, conversion methods, `toJSON`, or arbitrary guest code. Any required guest computation appears before the request through normal trace operations. Unsupported codecs, cycles, alias-sensitive transport cases, or scalar encodings are rejected under the registered transport contract rather than silently coerced.

Dispatch only after the entire request and its argument computation have committed. Subsequent mutations cannot change the captured request payload. Replay never invokes live host adapters.

Compare ordered requests and their exact semantic arguments/materialized payloads, not only a final store snapshot. The two-store fixture must retain `store("n",5)` followed by `store("n",8)`.

### 11.2 Delivery and fixture environments

Keep private input arrival separate from guest-visible delivery. A public observation must correspond to an already committed request and a permitted delivery state. It enters observed context at delivery, with no generation loss. Synchronous host results also cross an explicit observed boundary when they contain external facts.

### 11.3 Owned jobs and completion policy

Carry the existing supported single-agent queue semantics into public execution. Promise callbacks on already settled promises remain queued. Nested microtasks append in the correct FIFO order. Supported await/reaction cleanup behavior preserves or replaces the prior outcome correctly.

Specify typed public state transitions for owned promise creation, fulfillment/rejection/adoption, reaction and await registration, microtask enqueue, and ready-job dispatch. These may be declared builtin effects within the existing operation families, but each requires a schema, committed-state transition, and independent check. They derive state only from generated values and delivered observations. `queueMicrotask` registers work without immediately opening a callback activation; legal FIFO dispatch opens it after the current stack unwinds. A reaction has a scheduling owner and result promise distinct from a synchronous caller/return destination. An async call exposes its promise handle separately from its body's eventual completion, which settles that promise. Resuming `await` continues the existing activation and never creates a duplicate invocation.

Model fragments, lane assignment, region boundaries, and segment rollover never create guest service points. Delivery and job execution occur only at allowed semantic boundaries. Track legal ready-job order using committed state, without exposing future arrivals.

Update `export.js`, `visibility.js`, `causal-audit.js`, `schedule.js`, `controller.js`, `reference.js`, `rollout.js`, and admission logic together. The current synchronous guards and rejection of post-prefix observations must be replaced by the declared capability/completion contracts, not simply disabled.

The existing `queueMicrotask` tests expecting `abbc` and `123` are mandatory end-to-end training/controller fixtures in addition to their runtime replay coverage. Retain the declared bounded queue limits and explicit unsupported classifications.

## 12. Semantic groups, transport, and continuation

Track five separate quantities: logical reasoning records, primitive calculations, serialized fragments, model prediction/commit groups, and model tokens/compute. A longer line is not more recurrence; a JSON fragment is not an extra reasoning step.

Group only work permitted by the selected bounded policy. A consumer cannot use another generated record's newly produced bytes in the same parallel prediction group. Fused primitive expressions are explicitly one bounded prediction task; split them when the chosen operation or token budget requires a committed intermediate.

Use the pinned megatoken tokenizer/codec for real token counting. Read actual consumer limits from its pinned configuration; do not substitute byte counts or stale documented limits. Provide a deterministic target of up to 512 output tokens per logical payload, capped by the real consumer capacity, and enforce `operatorCount <= 8` in a fused pure region together with the expression-node bound. The conservative explanatory policy remains more granular.

Flush at required choices, effectful/unknown guest calls, relevant shared mutations, observations, requests, completion transfers, suspension/resumption, or policy limits. Derive the flush policy from static information and committed history. Transport fragmentation uses a separate deterministic framing contract and never exposes partial mutations, incomplete requests, or uncommitted call results.

Implement automatic continuation at committed semantic boundaries when the model history budget requires it. A continuation packet contains only the selected execution's committed state:

- Required static code and semantic source maps.
- Live activations, ordinary locals, shared captured cells, and pending completion values.
- Reachable object graph with identities, aliases, presence, and array state.
- Outstanding committed requests and delivered observations.
- Supported promises, suspended continuations, required pending callbacks, and legal queue order.
- The semantic point from which selected generation resumes.

Use static conservative liveness plus current semantic state to construct packets; do not use the reference future to decide which values survive. Keep semantic identities stable. Support multiple observed packet fragments when needed. Finish an open semantic record before a semantic rollover; byte-transport continuation may buffer incomplete framing but may not change guest state.

For selected execution, retain witness-defined bindings and synthesized temporaries until their explicit lifetime ends or a liveness proof valid for that selected continuation permits removal. Source-only liveness cannot discard a value introduced by an alternative derivation. When no applicable proof exists, retain the active binding conservatively and account for its packet cost. Preserve witness-name mappings as well as the referenced values.

If live state cannot fit declared bounds, produce a precise resource-limit result. Never truncate required state, restore a teacher heap, or label a prefix as completed. Segment siblings remain in the same dataset split.
