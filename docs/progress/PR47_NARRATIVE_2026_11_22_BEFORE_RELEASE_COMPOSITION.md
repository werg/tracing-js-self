## Lessons and acceptance rules

- Computed property expressions and mutation aliases require conservative source ownership analysis. A guard that misses an unsupported mutation can certify a guest throw where original JavaScript succeeds; passing a bounded positive cohort does not establish that guard's completeness.
- A validated interrupted checkpoint can continue the same optimizer/RNG/sampler trajectory under a new invocation cap when the objective identity explicitly excludes that cap. Preserve original bytes and prove the final global step and cumulative exposure.
- A timed-out job with a buffered, truncated test report leaves the completed population unknown. Preserve it and stream future progress separately from final JUnit; CI wall-time changes must not relax semantic or model deadlines.
- A downloaded archive may omit hidden operational files. Preserve original transport bytes; a newly created lock in a labeled copy is local exclusion, never reconstructed original-host authority. Complete data/model archives need durable retention beyond expiring Actions artifacts.

- Computational identity must bind verified input content, while physical paths remain provenance. Include empty prepared roots; validate lineage before constructing or restoring the model. A path move must not authorize a changed objective or revive old path-bound receipts.
- Extracting shared implementation code changes what an existing file pin protects. Bind and verify the helper's exact bytes before execution, and retain it in release/restorer receipts.

- A future queued operation's identity must be reserved immediately; retained reservations must bind their complete shape, owner and causal metadata before subscription or restoration.
- Parent test groups are not additional leaf checks, and a focused rerun does not become the original full gate.
- Command normalization is part of the authorization boundary. Every accepted spelling must pass the same durable checks **before** mutation or journal supersession.
- Reservation, initialization, coordinator commit and close are distinct mutations. Native completion, a transport receipt and runnable host-history recovery are separate claims.
- Storage publication attempts can leave an uncertain durable request even when the caller sees an error. Subsequent operations must remain fenced until independently reconciled.
- Returned results must agree with the full preserved native state, not only a rewritten hash or selected identity fields. A known closed outcome cannot authorize new work.
- Source eligibility, tokenization/packing, optimizer exposure, exact scored positions and learned success have different denominators and require different evidence. Lexical and reconstruction counts overlap.
- Resume history must be bound to checkpoint step, metadata and monotonically valid per-selector deltas. Stage transitions archive prior exposure; they do not credit it toward the new objective.
- A complete entry-point inventory is a migration map, not behavior parity. A two-mode edition pilot does not classify a 102,994-variant catalog.
- Preserve initial failures, explicit skips, raw logs, original hashes and runtime differences. Do not count overlapping reruns as new populations or use historical pins to qualify later trees.
- Concurrent increments are composed from explicit source maps and checked trees, with every distinct assertion retained. No frozen training run is cancelled or relabeled to accommodate later code.
